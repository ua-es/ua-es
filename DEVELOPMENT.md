# Development and deployment

## Quick start

Requirements: Node.js 22 or newer and Python 3. GNU Make is needed only for
`make` commands.

```sh
npm ci
make dev
```

`make dev` builds assets, watches `src/` for changes, and serves the site at
<http://localhost:8000/>. Stop both background processes with `Ctrl-C`. To use
another port, run `make dev PORT=8080`.

To preview the site without running tests or watching for changes, use
`make serve` and open <http://localhost:8000/>. It rebuilds the generated assets
before starting the server.

## Common commands

| Command                  | What it does                                                    |
| ------------------------ | --------------------------------------------------------------- |
| `make install`           | Install exact npm dependencies from `package-lock.json`.        |
| `make build`             | Generate production JavaScript and CSS assets.                  |
| `make check`             | Run unit and Chromium end-to-end tests.                         |
| `make format`            | Format JavaScript, CSS, and translation sources.                |
| `npm run format:check`   | Check formatting without changing files.                        |
| `make watch`             | Build once, then rebuild when files in `src/` change.           |
| `make serve`             | Build assets and serve the site at `http://localhost:$(PORT)/`. |
| `make dev`               | Watch source files and serve the site for local development.    |
| `make help`              | Show available Make targets.                                    |

Set `PORT` to change the local server port, for example `make serve PORT=8080`.
Make targets install npm dependencies when needed. `make test` is an alias for
`make check`. To run tests, install Playwright's Chromium browser once with
`npx playwright install chromium`, then use `make check` (or `npm test`).
For a focused run, use `npm run test:unit` or `npm run test:e2e`.

## Source files and generated assets

Edit readable files in `src/`. The pages (`index.html`, `en/index.html`,
`es/index.html`, `ru/index.html`, `fr/index.html`) and the files under `js/` and `css/` are generated by
`make build`. Do not edit generated files by hand.

### Pages

- `src/html/page.html` — the single page template shared by all languages.
  Text and language-specific attributes are `{{key}}` placeholders.
- `src/languages.json` — the list of site languages (code, label, URL path).
- `src/content/<lang>.json` — page copy per language (uk, en, es, ru, fr). Keys are
  grouped by section id (for example `faq.t12` is a text of the `faq` section,
  `top.alt3` is an image description). Every catalog must contain the same keys.
- `tools/render-page.js` — fills the template; a missing key stops the build.

To change copy, edit the matching `src/content/<lang>.json` value. To change
layout, edit `src/html/page.html` once for all languages. To add text, add a
new `{{section.key}}` in the template and the key to every catalog. Unit
tests fail when the key sets differ.

`src/locales/` holds strings used by JavaScript at runtime (buttons, form
messages), while `src/content/` holds the static page copy.

### Adding a language

1. Copy `src/content/uk.json` and `src/locales/uk.json` to `<code>.json` and
   translate the values (keep keys, `{placeholders}` and links).
2. Add `{ "code": "<code>", "label": "<LABEL>", "path": "<code>/" }` to
   `src/languages.json`.
3. Run `make build test`; the page, `hreflang` links, language switcher and
   `sitemap.xml` are generated from the list.
4. Add the expected strings to the `languages` array in `tests/e2e/site.spec.js`.

### Styles

- `src/css/style/NN-*.css` — main site styles, split into numbered parts;
  they are joined in numeric order into `css/index.min.css`. The order defines
  the CSS cascade (later parts override earlier ones), so add new rules to the
  part where the component lives and do not renumber or reorder parts.
- `src/css/readability.css` — readability adjustments; generates
  `css/readability.min.css`.

### JavaScript

- `src/js/app.js` — shared page behavior for all locales, including event
  content and interactive UI.
- `src/js/contact-form.js` — contact form behavior, validation, and request
  message generation.
- `src/js/app-helpers.js` — shared DOM, city, and image helpers.
- `src/js/site-controls.js` — theme selector, mobile navigation, and dialogs.
- `src/js/photo-gallery.js` and `src/js/venue-gallery.js` — lightboxes and
  gallery navigation.
- `src/js/countdown.js` — timezone-aware event countdown.
- `src/js/i18n.js` — translation lookup with explicit errors for missing keys.
- Other shared features live in `src/js/`, including image handling,
  responsive images, language switching, and details refinement.

### Translations

`src/locales/` contains catalogs for all five languages. Keep their nested key
paths and interpolation placeholders in sync. Add UI text to all five catalogs
and use `window.i18n.t("feature.message")` in JavaScript. For interpolated
text, pass named values, for example
`window.i18n.t("gallery.counter", { current, total })`.

## Build and tests

`build.js` creates `js/shared.js`, the shared `js/app.js` bundle, and one locale
bundle per language. It also compiles both CSS files. Run `make build` to
regenerate them.

Playwright starts a local server and builds the site before browser tests.
`make check` (or `npm test`) runs unit tests and the complete Chromium
end-to-end suite. The unit tests also check that locale keys, translations, and
interpolation placeholders match across all languages.

## Deployment

The site is published to GitHub Pages automatically, only after the
`Quality checks` workflow succeeds on a push to `main`. The
`.github/workflows/deploy.yml` workflow builds the site, copies the files the
website needs (HTML, `css/`, `js/`, `assets/`, `images/`, `robots.txt`,
`sitemap.xml`) into `_site/`, and deploys that folder. Sources, tests, and
`node_modules` are not published. GitHub Pages must be enabled in the
repository settings (Settings → Pages → Build and deployment → Source: GitHub
Actions).

There is no `make deploy` target. A deployment can also be started manually
from the Actions tab (`workflow_dispatch`).
