# Architecture

The site is static: the browser receives ready-made HTML, CSS and JS files, and there is no server-side code.

## Pages

There is one HTML file per language: `index.html` (UA), `es/index.html`, `en/index.html`, `ru/index.html` and `fr/index.html`. The list of languages is defined in `src/languages.json`. The files are generated by the build from one template, `src/html/page.html`, and the per-language content catalogs `src/content/<lang>.json`. Markup changes in one place, and translations live apart from the layout. Catalog keys look like `section.type+number` (for example `faq.t12`, `top.alt3`). All languages have the same set of keys, which a test verifies. Texts needed by JavaScript at runtime are kept separately in `src/locales/`.

## Build (`build.js`)

| Input | Output | Note |
| --- | --- | --- |
| `src/html/page.html` + `src/content/<lang>.json` | `index.html`, `en/`, `es/`, `ru/`, `fr/` (`index.html`) | `tools/render-page.js` fills `{{key}}` placeholders; a missing key stops the build |
| `src/js/*.js` (except `app.js`) | `js/shared.js` | files are concatenated and minified; the cache is shared by all languages |
| `src/js/app.js` and its imports | `js/app.js` | ES modules are resolved by esbuild |
| `src/locales/<lang>.json` | `js/locale-<lang>.js` | puts the strings into `window.localeMessages` |
| `src/css/style/*.css` | `css/index.min.css` | parts are joined by number; the order defines the cascade |
| `src/css/readability.css` | `css/readability.min.css` | minification |
| `src/languages.json` | `sitemap.xml`, `hreflang` links, language switcher | one list drives all of them |

Generated files are kept in the repository because the pages link to them directly. They are never edited by hand: change `src/` and run `make build`.
There is a size budget: if a bundle exceeds 200 KB, the build prints a warning.

## `src/js/` modules

- `i18n.js`: string lookup by key; a missing key is an error.
- `app.js`, `app-helpers.js`: page event logic, cities, images.
- `contact-form.js`: builds the message for Telegram or email; nothing is sent to a server.
- `site-controls.js`: theme, mobile menu, dialogs.
- `photo-gallery.js`, `venue-gallery.js`: galleries and lightboxes.
- `countdown.js`: countdown to the event, aware of the time zone.
- `image-health.js`: retries failed image loads and reports errors.
- `language-switch.js`, `details-refinement.js`: language switcher, collapsible blocks and legal dialogs.

## Translations

All catalogs have the same key structure. `tests/locales.test.js` checks that the keys and the substitution variables (`{current}`, `{total}`) match.

## Images

All photographs and illustrations are stored in a single format, WebP, in `images/`. There are no per-format versions and no JS swapping: pages link to `images/name.webp` directly, and responsive images (the hero slider) use `srcset` with `-640`, `-960` and full-size versions. Vector graphics, fonts, video and `og.jpg` (the social preview) live in `assets/`.

To add a picture, put a `.webp` in `images/` (preferably no wider than 1600 px) and reference it in the template or a content catalog. Original PNG masters are not stored in the repository. A unit test fails on empty image files.

## Tests

- `tests/*.test.js`: unit tests (translations, countdown, logo, images) on `node --test`.
- `tests/e2e/site.spec.js`: Playwright scenarios in Chromium for desktop and mobile.

## CI and deployment

`quality.yml` runs the build and all tests. After it succeeds on `main`, `deploy.yml` builds the site and publishes the files to GitHub Pages.

## Styles

The main styles are split into 13 parts in `src/css/style/` (`01-base.css` ... `13-decoration-safe-zones.css`). The build joins them by number. The order matters: the CSS has many override layers (for example, rules for the menu, maps and events are described again in different parts), so parts must not be reordered. Large files were split at rule boundaries without changing the order, so the built result is identical to the original. Merging the repeated rules by component needs visual tests.

`13-decoration-safe-zones.css` comes last on purpose: it positions the botanical branches so that they never overlap the text column.
