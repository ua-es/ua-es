# Архітектура

Сайт статичний: браузер отримує готові HTML, CSS і JS-файли, жодного серверного коду немає.

## Сторінки

Є три HTML-файли, по одному на мову: `index.html` (UA), `es/index.html`, `en/index.html`. Вони створюються збиранням з одного шаблону `src/html/page.html` і каталогів тексту `src/content/<мова>.json`. Розмітка змінюється в одному місці, а переклади лежать окремо від верстки. Ключі в каталогах мають вигляд `розділ.тип+номер` (наприклад `faq.t12`, `top.alt3`). Різні мови мають однаковий набір ключів, це перевіряє тест. Тексти, які потрібні JavaScript під час роботи, лежать окремо, у `src/locales/`.

## Збирання (`build.js`)

| Вхід | Вихід | Примітка |
| --- | --- | --- |
| `src/html/page.html` + `src/content/<мова>.json` | `index.html`, `en/index.html`, `es/index.html` | `tools/render-page.js` підставляє `{{ключ}}`, відсутній ключ зупиняє збирання |
| `src/js/*.js` (крім `app.js`) | `js/shared.js` | файли склеюються й мініфікуються, кеш спільний для всіх мов |
| `src/js/app.js` та його імпорти | `js/app.js` | ES-модулі розкриваються esbuild |
| `src/locales/<мова>.json` | `js/locale-<мова>.js` | кладе тексти у `window.localeMessages` |
| `src/css/style/*.css` | `css/index.min.css` | частини з'єднуються за номерами, порядок визначає каскад |
| `src/css/readability.css` | `css/readability.min.css` | мініфікація |

Згенеровані файли лежать у репозиторії, бо сторінки на них посилаються напряму. Вручну їх не редагують: зміни вносяться в `src/` і запускається `make build`.
Є бюджет розміру: якщо бандл більший за 200 КБ, збирання виводить попередження.

## Модулі `src/js/`

- `i18n.js`: пошук рядків за ключем, помилка на відсутній ключ.
- `app.js`, `app-helpers.js`: подієва логіка сторінки, міста, зображення.
- `contact-form.js`: формування звернення для Telegram або пошти, відправки на сервер немає.
- `site-controls.js`: тема, мобільне меню, діалоги.
- `photo-gallery.js`, `venue-gallery.js`: галереї та лайтбокси.
- `countdown.js`: зворотний відлік до події з урахуванням часового поясу.
- `image-health.js`: повторна спроба завантаження зображення й повідомлення про помилку.
- `language-switch.js`, `details-refinement.js`: перемикач мови, робота зі згорнутими блоками.

## Переклади

Три каталоги мають однакову структуру ключів. Тест `tests/locales.test.js` перевіряє збіг ключів і змінних підстановки (`{current}`, `{total}`).

## Зображення

Усі фотографії й ілюстрації зберігаються в одному форматі, WebP, у папці `images/`. Окремих версій для різних форматів і JS-підміни немає: сторінки посилаються на `images/назва.webp` напряму, а для адаптивних зображень (hero-слайдер) використано `srcset` з розмірами `-640`, `-960` та повною версією. Векторна графіка, шрифти, відео й `og.jpg` для прев'ю в соцмережах лежать в `assets/`.

Нова картинка: додайте `.webp` у `images/` (бажано шириною не більше 1600 px) і вкажіть її в шаблоні або каталозі тексту. Вихідні PNG-оригінали в репозиторії не зберігаються.

## Тести

- `tests/*.test.js`: юніт-тести (переклади, відлік, логотип) на `node --test`.
- `tests/e2e/site.spec.js`: сценарії Playwright у Chromium для настільної та мобільної версій.

## CI і публікація

`quality.yml` запускає збірку й усі тести. Після його успіху на `main` `deploy.yml` збирає сайт і публікує файли в GitHub Pages.

## Стилі

Основні стилі розбито на 12 частин у `src/css/style/` (`01-base.css` ... `12-cooperation-together-venue.css`). Збирання з'єднує їх за номером. Порядок важливий: у CSS багато шарів перевизначень (наприклад, правила для меню, карт і подій повторно описані в різних частинах), тому частини не можна міняти місцями. Великі файли розбито за межами правил без зміни порядку, результат збірки ідентичний вихідному. Подальше об'єднання повторів по компонентах потребує візуальних тестів.
